# ADR-0006：標籤庫是凍結的手工資產，不建立產生流程

**狀態**：已接受（2026-08-15）

## 背景

`js/tags.json` 是 436KB、3981 筆 `{en, zh, cat}`，涵蓋 134 個兩層分類（`人物/眼睛`、`服飾/上衣`、`表情動作/手部動作(拿著某物)`、`畫面/藝術風格`…）。它是自動完成的資料來源，也提供 chip 上顯示的中文翻譯。

**repo 裡沒有任何產生器。** `js/format_tags.py` 只是把 JSON 重新排版，不產資料。所以那些中文翻譯和那套分類是手工累積的。

這是專案裡最難重現的資產 —— Python 端 46 行的合併邏輯任何人二十分鐘可以重寫，這份標籤庫不行。

兩個選項：

- **凍結快照** —— 夠用就好，缺標籤時手動補一筆。
- **活資產** —— 建立匯入／去重／檢查流程，甚至與 Danbooru 標籤頻率或 Illustrious 實際詞彙對齊。

## 決定

**凍結。** 不建立產生、同步或驗證流程。缺標籤時直接手動編輯 `tags.json`。

理由：3981 筆對單人 txt2img 已經足夠；而且**上游沒有東西可以同步** —— 中文翻譯和那套分類是自己的創作，Danbooru 那邊生不出來。建流程等於為一個不存在的來源蓋管線。

## 後果

- `js/format_tags.py` 保留為手動編輯後的排版工具，不擴充成 pipeline。
- 標籤庫的品質由手工維持，沒有自動檢查。可接受，因為使用者是唯一的消費者。
- 若日後發現確實是從某個來源批次轉出、而且會重跑，這個決定要推翻，並把來源記進新的 ADR —— 否則下次連自己也想不起來。
- 這份分類法目前**不**用於把 chip 自動歸位到區塊，理由見 `CONTEXT.md` 的「分類」條目。
